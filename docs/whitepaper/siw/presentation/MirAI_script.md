### S14 — 개발 방법론: DDD + TDD *(약 1분)*

> "어떻게 만들었나"의 시작. 기술 자랑이 아니라 "왜 이렇게 했는가"로.

---

"이제 어떻게 만들었는지 보겠습니다."

"저희는 두 가지 원칙을 세웠습니다."

*(왼쪽 — DDD)*

"서비스는 DDD — Domain-Driven Design.
사용자 시나리오를 분석하고, 기능 중심으로 서비스 흐름을 설계하고, 기능 단위로 경계를 설정합니다.
Over Engineering 하지 않습니다. 팀이 완벽히 제어 가능한 최적의 기술만 사용합니다."

*(오른쪽 — TDD)*

"엔진은 TDD — Test-Driven Development.
완료 기준을 Given/When/Then으로 먼저 정의하고,
Red — 실패하는 테스트를 쓰고,
Green — 통과하는 최소한의 코드를 짜고,
Refactor — 품질을 개선합니다."

"본질 중심 테스트 코드로, 핵심 로직의 결함 방지에 집중했습니다."
