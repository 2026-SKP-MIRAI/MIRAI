# engine/app/routers/

## 목적
FastAPI API 엔드포인트 정의. `/resume`, `/interview` 등 라우트를 기능별로 분리.

## 구조
```
routers/
├── resume.py      이력서 관련 엔드포인트
│                  /api/resume/parse       — PDF 파싱
│                  /api/resume/analyze     — PDF 파싱 + targetRole 추출 (#113)
│                  /api/resume/target-role — resumeText → targetRole 단독 추출 (#113)
│                  /api/resume/questions   — 면접 질문 생성
│                  /api/resume/feedback    — 서류 피드백 (targetRole 선택 입력, 미입력·빈값 시 "미지정 직무", #113)
├── interview.py   면접 질문 생성 엔드포인트 (/api/interview/*)
├── report.py      8축 역량 평가 리포트 엔드포인트 (/api/report/generate) ← Phase 2
└── practice.py    연습 피드백 엔드포인트 (/api/practice/feedback) ← Phase 3
```

## 역할
- 요청 수신 → parsers/services 호출 → 응답 반환
- 인증 로직 포함 금지 (서비스 게이트웨이 패턴 — Next.js가 인증 담당)
- 타입은 `schemas.py`의 Pydantic 모델 사용

## async 설계 원칙

모든 라우터 핸들러는 `async def`로 선언한다.

- **현재 (Phase 2)**: `async def` + `asyncio.to_thread()` → sync 서비스 호출을 ThreadPool에서 실행, event loop 블로킹 없음 (#288)
- **Phase 3 전환 시**: `async def` 유지, 내부를 `AsyncOpenAI + await`로 교체만 하면 됨

`def`(동기)로 선언하면 Phase 3 전환 시 시그니처를 다시 바꿔야 하므로 `async def`를 유지하는 것이 확장성 측면에서 올바른 결정이다.

### resume.py 동시성 제한

`_OCR_SEMAPHORE = asyncio.Semaphore(2)` — OCR 동시 실행 최대 2개 제한.
t3a.micro (RAM 1GB) 기준 이미지 PDF OCR 1회 ~190MB 사용, 동시 3개 이상 시 OOM 위험.
LLM 호출(`generate_questions`, `generate_resume_feedback` 등)은 Semaphore 미적용 (네트워크 I/O, 메모리 부담 없음).
