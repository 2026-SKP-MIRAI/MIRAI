# engine/tests/e2e/

## 목적
실제 LLM + 실제 엔진 서버를 대상으로 면접 세션 전체를 자동 완주하고,
8축 역량 점수를 수집·비교하는 E2E 테스트 에이전트.

프롬프트 개선·모델 변경 효과를 정량 지표(mean/std/delta)로 측정하는 기반 인프라.

## 구조
```
e2e/
├── agent.py              CandidateAgent — 지원자 역할 LLM 답변 생성기
├── runner.py             SessionRunner — 전체 면접 HTTP 흐름 자동화
├── reporter.py           SessionResult 저장 + 통계 계산 (mean/std/delta)
├── conftest.py           e2e 전용 픽스처·skip 제어
├── test_agent_unit.py    단위 테스트 (mock LLM, CI 항상 실행)
├── test_agent_session.py E2E 통합 테스트 (RUN_E2E_AGENT=true 필요)
├── prompts/
│   ├── candidate_v1.md   기본 지원자 페르소나 (STAR 구조, 200~400자)
│   └── candidate_v2.md   A/B 비교용 페르소나 (간결, 80~200자)
└── results/              실행 결과 JSON (gitignored — 이력서 텍스트 포함 주의)
```

## 실행 방법

### 단위 테스트만 (CI 기본 — 비용 없음)
```bash
cd engine
pytest tests/e2e/test_agent_unit.py -v
```

### E2E 테스트 (실제 서버 + 실제 LLM 필요)
```bash
# 1. 엔진 서버 구동
docker run -d -p 8000:8000 --env-file .env mirai-engine

# 2. E2E 실행
cd engine
RUN_E2E_AGENT=true ENGINE_BASE_URL=http://localhost:8000 pytest tests/e2e/test_agent_session.py -v -s
```

### A/B 비교 실행
```bash
RUN_E2E_AGENT=true pytest tests/e2e/test_agent_session.py::TestABComparison -v -s
```

## 불변식

1. `agent.py`는 `app.*` 임포트 금지 — 엔진 내부 서비스에 의존하지 않는다
2. `runner.py`는 실제 HTTP 요청만 사용 (TestClient 아님)
3. `results/`에 저장된 JSON을 절대 커밋하지 않는다 (이력서 텍스트 포함)
4. `RUN_E2E_AGENT=true` 없이는 E2E 테스트가 자동 skip된다
5. `test_agent_unit.py`는 CI에서 항상 실행 (mock LLM, 비용 없음)

## 환경변수

| 변수 | 기본값 | 설명 |
|------|--------|------|
| `RUN_E2E_AGENT` | (없음) | 설정 시 E2E 테스트 활성화 |
| `ENGINE_BASE_URL` | `http://localhost:8000` | 엔진 서버 주소 |
| `OPENROUTER_API_KEY` | (없음) | 에이전트 LLM 호출용 API 키 |
| `CANDIDATE_MODEL` | `google/gemini-2.5-flash` | 에이전트 답변 생성 모델 |

## 규칙 변경 시 컨펌 필요
이 파일에 기재된 규칙과 충돌하는 변경을 하려는 경우, 작업을 진행하기 전에 반드시 사람(팀원)에게 먼저 확인을 받아야 한다.
