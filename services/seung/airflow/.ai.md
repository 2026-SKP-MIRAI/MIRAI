# airflow — seung 면접 분석 데이터 파이프라인

## 목적
seung DB(Supabase Postgres)에서 매일 면접 세션 데이터를 추출하여 S3에 집계 결과를 적재하는 Airflow 배치 파이프라인.

## 구조
- `dags/seung_analytics_dag.py` — 일배치 DAG (extract → compute → load → alert)
- `tests/` — pytest 단위 테스트
- `docker-compose.yml` — Airflow standalone (webserver + scheduler)

## 실행
EC2에서: `docker compose up -d`
Airflow UI: http://{EC2_IP}:8080

## 아키텍처 불변식 4 예외 사항
이 DAG는 seung Postgres DB에 psycopg2로 직접 접근한다.
이는 아키텍처 불변식 4("DB는 서비스가 소유")의 **의도적 예외**다.
- 이유: Python 배치 파이프라인에서 Prisma ORM 사용 불가
- 완화 조건: `seung_db_readonly` 읽기 전용 역할(SELECT 전용) 사용
- 기술부채 트리거: 두 번째 DAG가 app DB 접근 필요 시 내부 export API 분리 검토

## AWS 자격증명 방식
EC2 IAM Instance Role 사용 — boto3가 자동으로 Role 자격증명을 주입.
`AWS_ACCESS_KEY_ID` / `AWS_SECRET_ACCESS_KEY`를 코드나 환경변수에 명시하지 않는다.

IAM Role에 필요한 최소 권한:
- `s3:GetObject` — Raw Zone 읽기 (compute_metrics)
- `s3:PutObject` — Raw/Processed Zone 쓰기 (extract_sessions, load_to_s3)
- 리소스: `arn:aws:s3:::mirai-seung-analytics/*`

## 필요 환경변수 (EC2 ~/.env.seung-airflow)
- `SEUNG_S3_ANALYTICS_BUCKET` — S3 버킷명
- `SEUNG_DB_READONLY_CONN` — postgresql://seung_readonly:pw@db.xxx.supabase.co:5432/postgres
- `AIRFLOW_SECRET_KEY` — Airflow webserver secret key
