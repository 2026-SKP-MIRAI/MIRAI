# services/fint/ — Fint 서비스 (카카오톡 채팅 UI 모바일 AI 모의면접)

> 최종 업데이트: 2026-03-25 (이슈 #194 — services/lww → services/fint 디렉토리 통일)
> 이전: 2026-03-23 (이슈 #187 — UI/UX 전면 개선, 스토리보드 26화면 상세화, 디자인 시안)
> 관련 스펙: `docs/specs/fint/` | 기획서: `docs/whitepaper/lww/proposal.md`

## 목적
카카오톡 채팅 UI 기반 모바일 AI 모의면접 서비스. 취준생이 로그인 없이 바로 면접을 경험하고, 결과 리포트를 받는 "선 체험 후 가입" 구조. **Duolingo for 면접** 컨셉.

**핵심 원칙**: 재미 1순위. 코인 = 게임머니 (현금화 없음).

### Phase 1 — 자소서 업로드 + 면접 맞춤 질문 연동 (이슈 #180, 2026-03-25)

**개요**: 로그인 유저가 PDF를 업로드하면 Supabase Storage(`resumes` 버킷)에 저장하고, 면접 시작 시 자소서 텍스트를 엔진에 전달해 맞춤 질문을 생성한다.

**핵심 설계**:
- 1인 1파일 upsert 모델 — `resumes` 테이블 `UNIQUE(user_id)`, 교체 시 이전 Storage 파일 삭제
- parse-first 업로드 시퀀스: 엔진 `/api/resume/parse` 성공 후 Storage 저장 → DB upsert (DB 실패 시 Storage 롤백)
- 면접 시작 시 자소서 없으면 기존 직군 기반 `resumeText` fallback 유지 (하위 호환)

**신규 라우트**:
- `POST /api/resume/upload` — 인증 필수, PDF 검증(5MB/PDF-only), parse-first 저장
- `GET /api/resume` — 현재 저장된 자소서 메타데이터 반환

**신규 파일**:
- `src/lib/resume-storage.ts` — `uploadResumePdf`, `deleteResumePdf` (Service Role Key, `crypto.randomUUID()`)
- `src/app/api/resume/upload/route.ts` — upload 라우트
- `src/app/api/resume/route.ts` — GET 라우트

**수정 파일**:
- `src/lib/engine-client.ts` — ALLOWED_PATHS에 `/api/resume/parse` 추가
- `src/app/api/interview/start/route.ts` — `getCurrentUserId()` 조회 후 `resumes` 테이블에서 `resume_text` 주입
- `src/app/resume/page.tsx` — GET /api/resume로 현재 자소서 표시 + 교체 UI
- `src/components/UploadForm.tsx` — 파일 크기 제한 10MB→5MB

**DB 스키마** (Supabase Dashboard에서 수동 생성 필요):
```sql
CREATE TABLE resumes (
  id           UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id      UUID NOT NULL REFERENCES auth.users(id) ON DELETE CASCADE,
  file_name    TEXT NOT NULL,
  storage_key  TEXT NOT NULL,   -- {userId}/{uuid}.pdf
  resume_text  TEXT,            -- 엔진 /api/resume/parse 추출 텍스트
  created_at   TIMESTAMPTZ DEFAULT now(),
  updated_at   TIMESTAMPTZ DEFAULT now(),
  UNIQUE(user_id)
);
ALTER TABLE resumes ENABLE ROW LEVEL SECURITY;
CREATE POLICY "Users can manage own resumes" ON resumes FOR ALL
  USING (auth.uid() = user_id) WITH CHECK (auth.uid() = user_id);
```

**환경변수**: `SUPABASE_STORAGE_BUCKET` (버킷명, 기본값 없음 — 반드시 설정), `SUPABASE_SERVICE_ROLE_KEY` (Storage 서버사이드 업로드)

### UI/UX 확정 사항 (E2E 검증 완료)

- **채팅 레이아웃**: 상단 고정 방식. 첫 번째 아이템으로 시스템 배너("🎙️ AI 면접이 시작됐어요!") 삽입
- **진행 카운터**: `displayIndex = Math.min(questionIndex + 1, total)` — Q1 시작 시 "1/5" 표시
- **면접 완료 카드**: `(state.status === "ending" || isEnding)` 조건으로 렌더링
- **터치 타깃**: 직군 칩 `min-h-[44px]`, 스킵 버튼 `min-h-[44px] min-w-[44px]` (WCAG 2.1 AA)
- **점수 색상**: 낮은 점수 `red` → `amber` (덜 위협적인 UI)
- **텍스트 입력**: `overflow-y-auto` (이전 `overflow-hidden` → 긴 텍스트 잘림 방지)
- **resume 페이지**: 루트 div에 `w-full` 필수 — body `align-items: center` 때문에 회색 거터 방지
- **MobileShell 밖 페이지**: body가 `display:flex; align-items:center; background:#d1d5db` — `(main)`, `(interview)` 그룹 밖 페이지는 반드시 루트 div에 `w-full` 추가

## 인증·DB·스토리지

### 인증 아키텍처 (Phase 1, 이슈 #179)

**익명 우선 원칙**: Fint는 SIW/Seung과 달리 미들웨어에서 비로그인 사용자를 `/login`으로 리다이렉트하지 않는다.

| 구성 요소 | 역할 |
|-----------|------|
| `middleware.ts` | Upstash Redis sliding window rate limit (IP당 10req/min) → Supabase `getUser()` 세션 갱신 (리다이렉트 없음) |
| `app/auth/callback/route.ts` | OAuth 코드 교환 + `migrate_anon_to_user` RPC |
| `app/auth/confirm/route.ts` | 이메일 확인 링크 처리 (`verifyOtp`) |
| `app/(main)/login/page.tsx` | 소셜(카카오·구글) + 이메일 탭 로그인 UI |
| `components/interview/SaveAccountCTA.tsx` | 비로그인 면접 완료 후 로그인 유도 배너 |

**익명→인증 마이그레이션**:
1. OAuth 로그인 완료 → `/auth/callback` 호출 (또는 이메일 확인 → `/auth/confirm`)
2. `fint_anon_id` 쿠키 읽기
3. `migrate_anon_to_user(p_anon_id, p_user_id)` RPC 실행 (Supabase SQL 트랜잭션)
4. `interview_sessions` + `reports` 양쪽 `user_id` 원자적 업데이트
5. 마이그레이션 성공 후 `fint_anon_id` 쿠키 삭제 (재로그인 시 중복 마이그레이션 방지)

**dual-write 패턴** (interview API 라우트):
- `createClient()` + `getUser()` → `userId` 감지
- 로그인이면 `user_id = auth.uid()`, 비로그인이면 `user_id = null`
- `anonymous_id`는 항상 유지

### DB

- **DB**: Supabase PostgreSQL (스키마: `docs/specs/fint/dev_spec.md` §DB 스키마)
  - 테이블: `interview_sessions`, `reports`, `profiles`
  - RLS 정책: 비로그인은 `anonymous_id` 검증, 로그인은 `auth.uid()` 검증
  - Supabase RPC: `migrate_anon_to_user(p_anon_id text, p_user_id uuid)` — 원자적 마이그레이션
- **스토리지**: Supabase Storage — 버킷명 `SUPABASE_STORAGE_BUCKET` 환경변수 (하드코딩 금지)
- **보안**: `SUPABASE_SERVICE_ROLE_KEY`는 서버 전용 — `NEXT_PUBLIC_` 절대 금지

| 기능 | 엔진 엔드포인트 | 서비스 타임아웃 |

**엔진 Stateless 패턴**: 매 호출 시 `history`와 `questionsQueue` 전체를 전달해야 함. 서비스가 DB에 보관 후 전달.

## 환경변수

`.env.example` 참조. 주요 변수:
- `ENGINE_BASE_URL` — 엔진 서비스 URL
- `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY` — Supabase 클라이언트
- `SUPABASE_SERVICE_ROLE_KEY` — 서버 전용
- `NEXT_PUBLIC_SITE_URL` — Supabase Auth 대시보드 Site URL 설정 참조용
  - OAuth redirect URL은 코드에서 `window.location.origin` 기반 동적 생성 (Vercel Preview 호환)
  - Supabase 대시보드: Authentication → URL Configuration → Site URL + Redirect URLs 설정 필수
- `UPSTASH_REDIS_REST_URL` — Upstash Redis REST URL (rate limiting용, Vercel 대시보드 등록 필수)
- `UPSTASH_REDIS_REST_TOKEN` — Upstash Redis REST Token (rate limiting용, 서버 전용)
