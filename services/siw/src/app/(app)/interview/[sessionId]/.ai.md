# interview/[sessionId] — 면접 세션 페이지

## 목적
실시간 면접 진행 페이지. 질문 표시, 답변 입력, SSE 스트리밍 피드백, 세션 완료 처리를 담당한다.

## 파일 구성
- `page.tsx` — 메인 면접 세션 페이지 (use client)
- `report/page.tsx` — 면접 리포트 페이지

## 주요 상태 (page.tsx)
- `currentQuestion` — 현재 표시 중인 질문
- `answer` — 사용자 답변 입력값 (최대 5000자)
- `submitting` — 답변 제출 중 여부
- `streamingText` / `streamingPersona` — SSE 스트리밍 피드백
- `interviewMode` — "practice" | "real"
- `sessionInterrupted` — sessionStorage miss 시 복구 안내 표시
- `lastSubmittedAnswer` — 마지막 제출 답변 (네트워크 끊김 시 재전송용)

## 면접 모드
- **real(실전)**: `/api/interview/answer` 호출 → SSE 스트리밍 피드백 표시
- **practice(연습)**: `/api/interview/answer` 호출 → 피드백 없이 다음 질문으로 바로 진행
  - `InterviewChat.tsx`의 피드백 UI가 `interviewMode === "real"` 조건으로만 렌더링됨

## 답변 제한
- 5000자 카운터 표시 (`{answer.length} / 5000`)
- 초과 시 경고 메시지 표시 (amber-600, 저장은 서버에서 별도 제한)

## 세션 복구
- 초기화 시 `sessionStorage.getItem()` 확인 — miss 또는 JSON 파싱 실패 시 `sessionInterrupted = true`
- SSE 스트림 끊김 감지 — `consumeAnswerStream` try/catch로 에러 전파
- SSE silent 종료 감지 — try/catch 밖 `!donePayload` 체크 (offline 시 `reader.read()` 가 `done:true` 반환하는 케이스)
- `fetch` 자체 실패 감지 — `handleSubmit` catch에서 `instanceof TypeError` 체크
- `handleRetryLastAnswer` — `lastSubmittedAnswer`로 마지막 답변 재전송

## 불변식
- 피드백 UI(InterviewChat)는 `interviewMode === "real"`일 때만 렌더링

## sessionStorage 키
- `interview-first-{sessionId}` — 첫 번째 질문 JSON
- `interview-mode-{sessionId}` — 면접 모드 ("practice" | "real")
